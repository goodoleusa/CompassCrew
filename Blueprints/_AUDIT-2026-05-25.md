## DIFFERENT-PURPOSE Notes

### Charter — dual-role template
The `Charter.blueprint` (vault) is designed as a **pseudosystem dossier note** — a mirror of `forensics/charters/active/{id}.json` with fields like `mission_id`, `canonical_repo_path`, sections for Thesis/Phases/Operator Pain Points. It is used when creating a navigable vault representation of an existing charter JSON.

The `Charter.njk` (hive) is designed as a **creation template** — it generates a new charter from scratch with the swarmy governance schema (charter_id, status, Scope, Anchors, Compass, Linked manifests dataview).

**Recommendation:** Keep both. Rename the hive version `Charter-New.njk` or leave as-is with documentation. The vault `.blueprint` is archived as part of this migration but the hive `.njk` serves the correct creation role.

### Flow-* (6 templates: Cryptographic, Evolution, Memory, Network, Orchestration, RAP)
The vault `.blueprint` versions are **standalone diagram notes** — each creates a full Obsidian note with rich frontmatter (type, subtype, compass N/S/E wiki-links, chain metadata). They are used to create a persistent navigable diagram in the vault.

The hive `.njk` versions are **reusable snippet templates** — minimal frontmatter (name, description, triggers), body is the composable diagram block inserted into any note. Both the vault note body and the hive snippet body contain the identical Mermaid diagram.

**Recommendation:** The vault `.blueprint` is archived. The hive `.njk` snippet replaces it. To create a standing diagram note, use "Swarmy: apply blueprint" to insert the snippet into a new note, then add rich frontmatter manually or extend the `.njk` as needed.
