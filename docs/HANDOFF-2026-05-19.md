## What's scaffolded but needs more work (NEXT AGENT)

### 1. Charter dashboard polish (`src/charter-dashboard.ts`)
The view works end-to-end (list → edit form → save). But the edit form currently has 4 hardcoded fields (`intent`, `success`, `eta`, `status`). The canonical charter shape is defined by `Blueprints/Charter.njk` and `faerie2/forensics/charters/SCHEMA.md`. Wire the form fields off the njk slot list so every charter field is editable, including `compass.N/S/E/W`, `anchors[]`, `cluster_prefix`, `deliverables_address_prefix`.

The "Set session in motion → spawn from this charter" button is a placeholder Notice. Wire it to `faerie_spawn` with the charter's `intent_address` joined as the mission. Likely 30 lines.

### 2. Excalibrain auto-layout reverse pass
The new layered layout in `autoLayoutFromFrontmatter` reads the canvas (not the source note's frontmatter). For full "auto-layout FROM frontmatter," it should:
1. Find the draft note's `draft_for: <source note>` frontmatter.
2. Read the source's `up/down/same/west` arrays.
3. Generate/update bearing rectangles to match (add missing, remove orphans).
4. Then run the layered layout.

Currently it only re-layers what's already on the canvas.

### 3. Server-side propose_bearings validation
`faerie_charter_update` writes the file but does NOT call `scripts/dev/coc/10-charter-validate.py` afterwards. Add a `_run_script(CHARTER_VALIDATOR, ["--id", charter_id])` pass and roll back the write if validation fails. See `mcp-wiring-map-2026-05-19.md` for the wiring audit.

### 4. Force-directed → layered for OTHER views
Hive uses ExcaliBrain (via `compass-overlay.ts`) for the typed graph view. ExcaliBrain itself uses force-directed by default. Investigate `obsidian-excalibrain-plugin/settings.json` to see if there's a `layoutAlgorithm: "hierarchical"` flag; if so, set it via the plugin's apply-preset command alongside the Excalidraw preset.

### 5. Mintlify-style dashboard polish
The user wants "all the dashboards rendering beautifully." Three panes need a visual pass:
- `FaerieLiveView` (`src/mcp-bridge.ts`) — currently raw `<pre>` JSON blocks. Replace with card grids per section.
- `SwarmyChatView` (`src/chat-panel.ts`) — bubble styling, markdown rendering of assistant replies (currently `setText` only).
- `FaerieChartersView` (`src/charter-dashboard.ts`) — already styled but could use status badges, ETA countdown, COC tail per charter.
